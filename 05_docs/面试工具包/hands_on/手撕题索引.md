## 三、repo 已有的三道题怎么复用（练法）

这三道在项目源码里就是按"面试手撕题"标准写的（注释密度极高），推荐流程：

1. **先读**：通读 `LruCache.h` / `BkTree.cpp` / `Searcher.cpp` 的头注释和函数注释——注释就是口播稿。
2. **再遮**：合上文件，白板或新文件里凭理解重写核心结构（LRU：get 命中 splice 到队头；BK-tree：按编辑距离分桶 + 三角不等式剪枝；TopK：堆满 k 后与堆顶比较再淘汰）。
3. **后对**：`git diff` 对答案（仓库基线提交 = 参考实现），漏掉的边界（如 LRU 先删索引再删节点防迭代器悬垂）就是复述重点。
4. 项目连接话术：LRU 讲"两级缓存里 L1 的实现，命中率口径 L1 ~30% + L2 ~40%"；BK-tree 讲"35 万词项词典免全量遍历"；TopK 讲"纠错建议词取前 k 个，O(n log k)"。

## 四、每题写完主动讲的三个点（写完代码别停嘴，按这个顺序讲）

### 1. 线程安全单例
- C++11 前后分水岭：无内存模型时 DCLP 无可移植正确写法（new 可重排成"先发布后构造"），volatile 不提供 happens-before；
- 局部静态是生产首选：标准 §6.7 保证并发初始化互斥等待，一行搞定还难写错；call_once 的加分点：初始化抛异常时保持"未执行"、后续可重试；
- DCLP 正确版的内存序配对：store(release) 发布指针 ↔ load(acquire) 读指针，保证看到指针即看到完整对象；锁内第二检可以 relaxed（mutex 已建立 happens-before）。

### 2. 线程池
- 虚假唤醒与谓词循环：`wait(lk, pred)` ≡ `while(!pred) wait(lk)`，裸 `if+wait` 会在空队列上 `front()` 崩溃；
- 谓词必须含 stop_：否则优雅关闭时 worker 睡死、析构 join 卡死；顺带讲清"排干策略 vs 丢弃策略"的选择依据（备份任务不能丢）；
- 池大小是推出来的：CPU 密集≈核数、IO 密集≈核数×(1+等待/计算)，拿 RIS 实战数字推一遍（4C8G、峰值 20 QPS、P99 80ms → 4 线程 50 QPS 上限、2.5 倍余量）。

### 3. 生产者消费者
- 一锁两 cv：not_empty / not_full 两个等待集合，notify 精准不空转；有界容量 = 反向压流，内存不爆；
- 谓词含 closed_ 的关闭语义：close() 叫醒所有阻塞方，消费者排干后收到"EOF"退出——进程收尾不死锁的关键；
- 对比信号量方案：信号量只表达"计数"，条件变量表达任意"条件"（满/空/关闭多条件时信号量版极易漏唤醒），且 sem_t 无 RAII、EINTR 要手动重试、macOS 已废弃匿名信号量。

### 4. 编辑距离
- DP 三步讲法：状态定义（前 i 变前 j 的最少操作数）→ 边界 → 三选一转移；复杂度 O(n×m)，滚动数组压空间到 O(min)（注意最后结果在 swap 后的 prev）；
- 中文必踩坑（真实事故）：一字 3 字节，一字之差按字节算距离 3 超过 max_dist=2 → 纠错空结果；先切码点再 DP 才正常召回（弹药库 §11"肺节结"案例）；
- 限界版剪枝：行最小值单调不减，超 limit 提前返回——BK-tree 查询（max_dist 通常 1~2）的实战优化，再点名带状 DP / Myers 位并行表示知道上限。

### 5. LRU（repo 版）
- 数据结构组合拳：list 维护访问序 + unordered_map 做 key→节点索引，get/put 都 O(1)，命中 splice 到队头；
- 淘汰的正确顺序：先删索引再 pop 节点（防迭代器悬垂）；capacity==0 的防御分支；
- 项目连接：L1 进程内 ~100ns、L2 Redis 跨进程 ~1ms，命中率合计 ~70%（L1 ~30% + L2 ~40%）。

### 6. BK-tree（repo 版）
- 原理一句话：把词典组织进度量空间，靠编辑距离满足三角不等式剪枝，只访问边权 ∈ [d-n, d+n] 的子树；
- 数字：35 万词项词典暴力是 35 万次 O(L²) DP，剪枝后典型只访问一成上下的节点；
- 构建即逐词 insert 按距离分桶；雷点：别把 BK-tree 说成二叉树/前缀树（按整体距离分桶，不是字符前缀）。

### 7. TopK 小顶堆（repo 版）
- 为什么小顶堆：维护 size=k 的堆，堆顶是"TopK 里最差的"，新元素只在胜过堆顶时入堆，O(n log k) vs 全排序 O(n log n)；
- 比较器设计：(distance, -freq) 双关键字——同距离优先高频词（业务语义进比较器）；
- 延伸：内存受限的海量数据 TopK 同款思路（堆不变形，换成磁盘流式喂入）；和快速选择 quickselect 的取舍（要全部前 k 且有序用堆，只要第 k 大可 O(n) 均摊）。
